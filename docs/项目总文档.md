## 1. 项目概述

**Video Content Analyzer（VCA）** 是面向短视频编导团队的**竞品视频反向拆解工具**。上传一条竞品视频后，系统**全本地**完成：

1. 画面关键帧抽取 + 特征分析（浏览器端 Canvas）
2. **Qwen3-ASR-1.7B** 本地大模型语音转写（GPU DirectML/Vulkan 加速，字级时间戳）
3. 关键词提取 + 文案脚本生成
4. **本地智能分析**：前 3 秒黄金钩子、音频能量曲线、视觉锚点、画面信息密度、字幕/花字 OCR
5. 可选：把「画面 + 转写 + 元数据」打包交给大模型，生成**九节结构化深度拆解报告**
6. 报告 / 帧图 / 历史记录 一键导出与持久化

> **当前形态**：单体 Flask 服务（一个进程同时提供 API 与前端静态页）+ 本地 SQLite 持久化。
> 历史 v2.0（FastAPI + Docker Compose + PostgreSQL/Redis/MinIO）已归档，**不参与运行**（见 §4.6）。

### 支持格式

- **视频格式**：MP4 / MOV / AVI / WebM
- **文件大小**：最大 600 MB
- **音频要求**：需含音轨（纯画面视频仅做画面与视觉分析）

## 2. 核心功能模块

### 2.1 视频上传与预览
拖拽或点击上传；左侧面板显示视频预览；实时元数据（时长 / 分辨率 / 帧率 / 总帧数 / 文件大小 / 音轨）；自动识别横竖屏。

### 2.2 画面智能分析（浏览器端）
按固定间隔抽帧，用 Canvas 逐帧计算（**无需服务端算力**）：

| 维度 | 说明 |
|------|------|
| RGB 色彩 | 平均 R/G/B，识别主色调 |
| 亮度 | 画面整体亮度 |
| 运动检测 | 帧间差异 → 运动强度 |
| 文字密度 | 画面文字区域占比 |
| 皮肤 / 白底 / 蓝屏 / 暗光 | 人物、产品白底、设备屏幕、电影感暗光 |
| 色调 / 饱和度 | HSV 色彩空间 |
| 镜头类型 | 人物特写 / 人物中景 / 产品展示 / 暗光场景 / 蓝色场景 |

### 2.3 语音转写（Qwen3-ASR-1.7B）
**流程**：上传视频 → 自动**提取音频**（状态 `audio_ready`）→ 前端点「开始转写」→ 调 `/api/transcribe-start` 启动 Qwen3-ASR。

- **引擎**：Qwen3-ASR-1.7B（本地 GGUF 解码器 + ONNX 编码器，DirectML/Vulkan GPU 加速，字级时间戳）
- **进度**：转写进度条 + 已耗时 + 百分比 + 详情日志 + 预估剩余时间
- **输出**：按时间戳分段的转写文本（`segments`）
- **并发**：强制串行（`MAX_CONCURRENT_TRANSCRIBE=1`），排队任务显示 `waiting` 状态

### 2.4 关键词提取
对转写文本做 NLP，输出四类关键词：**高频词 / 动作词 / 情绪词 / 产品核心词**。

### 2.5 视频文案脚本
按转写内容生成分段文案脚本，与口播逐段对应，便于编导对照改写。

### 2.6 关键帧预览与打包下载
关键帧网格预览（每帧带特征标签）；一键把「关键帧图片 + Markdown 报告」打包 ZIP 下载（前端 `jszip.min.js`）。

### 2.7 完整分析报告
自动生成 Markdown 报告：基本信息表、画面特征汇总、语音识别全文、关键词、帧数据明细、深度拆解（若已执行）。
- 「下载」导出 `.md`
- 「保存到项目目录」调 `POST /api/save-export`，报告与帧图落盘到 `exports/`（html / markdown / pic）

### 2.8 智能分析（本地，P0/P1）
> 页面「⚡ 智能分析」Tab。**全部本地运行，无云端上传。**

| 子功能 | 说明 |
|--------|------|
| 🎯 前 3 秒黄金钩子 | 基于画面+音频+文本判定**钩子类型**与**强度评分（0-100，分级）**，并给优化建议 |
| 🎵 全片音频能量曲线 | 逐秒 RMS 能量，标出内容高潮/重点段 |
| 🔥 视觉锚点 | 定位「最炸画面」并给建议 |
| 📊 画面信息密度 | 有效信息占比，提示画面空白/冗余 |
| 📝 字幕/花字 OCR | 识别画面字幕与花字（依赖 `paddleocr`，缺失时接口优雅降级 `available:false`） |

### 2.9 大模型深度拆解报告（九节结构）
把「画面分析 + 转写全文 + 视频元数据」打包发给 LLM，按**九节格式**生成报告。

**服务商**：硅基流动 SiliconFlow（默认）/ DeepSeek 官方 / Ollama（本地）/ 智谱 Zhipu。

| 节 | 内容 |
|----|------|
| 一句话总结（一行） | 核心结论 · 流量打法 · 叙事主权破局点 |
| 第一节 · 原文基础信息 | 逐字稿全文（繁转简）+ 表层口播逻辑 |
| 第二节 · 深度反向拆解 | 风格调性、观众心理路径、底层情绪、叙事主权 4 步（破霸权/建标准/立人设/收闭环）、跑量优势 |
| 第三节 · 口播逐段拆解 | 表格：预估时长 / 模块 / 原文 / 核心作用 / 叙事主权标注 / 算法增益 / 5A 标注 |
| 第四节 · 分镜头拆解 | 表格：镜头编号 / 时长 / 景别运镜 / 画面内容 / 对应口播 / 情绪流转 / 视觉实锤 |
| 第五节 · 5A 人群流转 | 表格：人群层级 / 作用强度 / 核心流转价值 / 流转路径 |
| 第六节 · 爆款文案库 | 表格：文案分类 / 内容 / 预估转化率 / 预估完播率 / 使用场景 |
| 第七节 · 可复刻对标行业 | 3-5 个相邻品类「推翻旧叙事 → 建立新标准」 |
| 第八节 · 团队落地执行要点 | 5-6 条可执行指令 |

> 5A 标注：A1（3 秒）/ A2（前三分位）/ A3（中段）/ A4（后三分位）/ A5（结尾）。

**交互（三步）**：选服务商 + 输入 Key →（校验 Key、拉模型列表）→ 选模型启动异步分析 → 查看 / 下载 / 重新分析。

**安全**：API Key 仅存浏览器内存（`<input type="password">`），随请求发到本地后端代理转发，**不落库**，刷新即清除。

### 2.10 历史记录（SQLite 持久化）
- 页面右上角「📜 历史记录」按钮 / 「历史记录」Tab，可**无需上传视频**直接查看
- 转写与各分析结果自动存本地 SQLite（`db.py`），**重启不丢失**

## 4. 技术架构

### 4.1 当前架构：单体 Flask 服务（运行中）
一个 Python 进程（`transcribe_server.py`，约 68 KB / 1912+ 行）同时承担：转写与分析 API、前端静态页 serve、前端依赖分发。

```
浏览器 ──HTTP/轮询──> Flask 单体（transcribe_server.py）
                        ├── SQLite(db.py) 任务与结果持久化
                        ├── Qwen3-ASR GGUF 引擎（懒加载，串行）
                        ├── media_analysis.py (P0：钩子/能量/人脸)
                        ├── p1_analysis.py   (P1：OCR/信息密度/视觉锚点)
                        └── requests → LLM API（仅深度拆解时联网）
```

### 4.2 当前技术栈

| 层面 | 当前实现 |
|------|----------|
| 后端框架 | Flask 3 + threading（单进程） |
| 任务存储 | 内存 `dict`（带线程锁）+ 落盘 **SQLite**（历史记录） |
| 语音识别 | **Qwen3-ASR-1.7B**（GGUF 解码器 + ONNX 编码器，`onnxruntime-directml` GPU 加速，`n_ctx=4096`） |
| 进度推送 | 前端轮询 `GET /api/status/{job_id}` |
| 画面分析 | 浏览器端 Canvas（10 维特征） |
| 本地智能分析 | `media_analysis.py` + `p1_analysis.py` |
| 持久化 | `db.py` → SQLite |
| LLM 拆解 | 硅基流动 / DeepSeek 官方 / Ollama / 智谱（四选一） |
| 文件存储 | 系统 temp 目录（用完即删） |
| 部署 | `python transcribe_server.py` 或 `start_backend.bat`（端口 8766） |

> ⚠️ **Whisper 已移除**：早期版本基于 Whisper（CPU + torch），现已全面切换为 Qwen3-ASR 本地引擎。

### 4.6 历史 v2.0 架构（已归档，非运行）
曾被规划并实现为生产级架构：**模块化单体 + 异步任务队列**，6 容器 Docker Compose：

| 容器 | 作用 |
|------|------|
| `vca-api`（FastAPI + uvicorn） | 接口服务（含 Auth/RateLimit/CORS 中间件链） |
| `vca-worker`（Celery） | 转写 / 分析 / 清理任务 |
| `vca-beat`（Celery Beat） | 定时清理 |
| `vca-postgres`（PostgreSQL 16） | 任务 / 转写 / 分析持久化 |
| `vca-redis`（Redis 7） | Broker + 缓存 + 进度 pub/sub |
| `vca-minio`（MinIO） | 视频对象存储 |

- **关键收益**：长任务不阻塞 Web → Celery 异步；状态持久化 → 重启不丢；进度 → WebSocket 实时推送；Key → AES-256-GCM 加密管理；含 `/health` `/ready` `/metrics`。
- **状态**：源码存于 `archive/legacy-fastapi-app/`，**当前未作为运行环境**，未来切换可从此恢复。详细设计与 DDL 见原《后端架构重构方案.md》。

## 5. 部署配置

### 5.1 结论速览

| 平台 | 能否本地部署 | 说明 |
|------|:--:|------|
| **Windows（配 DirectX 12 GPU）** | ✅ 支持 | 当前唯一开箱即用平台 |
| **macOS（含 M1/M2/M3）** | ❌ **不支持** | 依赖 `onnxruntime-directml`（Windows 专属），Mac 上 `pip install` 直接失败 |
| **Linux** | ⚠️ 需改造 | 同样受 DirectML 限制，需换 ONNX 执行后端（CoreML / CUDA / CPU） |

> 换 Qwen3-ASR 后，**本项目变为 Windows + GPU 应用**。此前"Mac M1 闭眼能跑"的结论已作废。

### 5.2 磁盘占用（实测）

| 组成 | 体积 |
|------|------|
| Qwen3-ASR 模型（`qwen3_asr_models/`） | **3,865 MB** |
| 引擎源码 + ONNX 运行时资源（`qwen3_asr_gguf_src/`） | 314 MB |
| Python venv（含 onnxruntime-directml / paddleocr / mediapipe 等） | 982 MB |
| **`backend/` 合计** | **≈ 5,162 MB（约 5 GB）** |

> 建议预留 **15 GB** 可用磁盘（含视频处理峰值）。旧的 Whisper 方案约 1.5 GB，新方案约 5.2 GB。

### 5.3 Windows 最低配置

| 维度 | 最低可运行 | 推荐流畅 |
|------|-----------|----------|
| **系统** | Windows 10 64 位（19041+） | Windows 11 64 位 |
| **CPU 架构** | x86-64（Intel/AMD） | 同左 |
| **CPU** | 四核 2.5 GHz 及以上 | 六核 i5 / Ryzen 5 及以上 |
| **GPU** | 支持 DirectX 12 的 GPU（近 5 年核显通常可用） | 独显（NVIDIA/AMD），显存 ≥ 4 GB |
| **内存** | **16 GB** | 32 GB |
| **磁盘** | 15 GB 可用（**SSD 必需**） | 30 GB NVMe SSD |
| **运行时** | VC++ 2019 可再发行、Python 3.10–3.12 | 同左 |

> ⚠️ **GPU 是硬要求**（`llm_use_gpu=True` 写死 + ONNX 走 DirectML）；**Windows on ARM 不支持**。

### 5.4 macOS 现状
当前代码**无法在 macOS 直接部署**：`onnxruntime-directml` 仅发布 Windows 版；ONNX 按 DirectML 初始化；`llm_use_gpu=True` 指向 DirectML/Vulkan 路径。
若要在 Mac 跑需改造（属「端口迁移」，建议走评审）：ONNX 后端换 CoreML EP、`llm_use_gpu` 改可配置、`requirements.txt` 拆分两套平台、模型无需更换。

### 5.5 Windows 部署步骤

```bat
:: 1. 建虚拟环境（Python 3.11 推荐）
python -m venv venv
venv\Scripts\activate
:: 2. 装依赖（含 onnxruntime-directml / paddleocr，体量大、耗时长）
pip install -r backend\requirements.txt
:: 3. 确认模型就位（约 3.8 GB）：backend\qwen3_asr_models\*.onnx + *.gguf
::    （可用环境变量 QWEN3_ASR_MODEL_DIR 指向别处）
:: 4. 启动（双击 start_backend.bat 亦可）
cd backend
python transcribe_server.py --host 0.0.0.0 --port 8766
:: 5. 浏览器打开 http://127.0.0.1:8766/
```

### 5.6 常见踩坑
1. 别用无 GPU 的机器/虚拟机：DirectML 需要 D3D12 设备，纯 CPU 起不来。
2. 磁盘要留够：模型 + 依赖约 5 GB，视频处理再吃 1–2 GB。
3. `paddleocr` 安装慢且大：暂不需要字幕 OCR 时可注释掉，P1 的 OCR 接口自动降级。
4. Python 优先 3.11（避开 3.13，部分轮子跟进滞后）。
5. Windows 必须 x64。
6. 深度拆解仍需联网（或本地 Ollama）。

### 5.7 与旧版（Whisper）差异

| 项 | 旧版（Whisper） | 新版（Qwen3-ASR） |
|----|----------------|------------------|
| 引擎 | Whisper（tiny/small/medium） | Qwen3-ASR-1.7B（ONNX+GGUF） |
| 依赖 | torch + openai-whisper | onnxruntime-directml + gguf + paddleocr |
| GPU | 不需要（CPU 即可） | **必需**（DirectML/Vulkan） |
| macOS | ✅ 支持 | ❌ 不支持（需移植） |
| 磁盘 | ~1.5 GB | ~5.2 GB |
| 内存 | 8 GB 底线 | 16 GB 底线 |
