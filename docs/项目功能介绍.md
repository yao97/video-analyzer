# Video Content Analyzer - 项目功能介绍文档

> 视频内容智能分析工具，上传视频 → Whisper 语音转写 → LLM 深度文案拆解与分镜头解构。

---

## 一、项目概述

**Video Content Analyzer（VCA）** 是一款面向短视频编导团队的竞品反向拆解工具。上传竞品视频后，系统自动执行语音转写（Whisper）、关键帧抽取、画面特征提取，并支持接入大语言模型生成九节结构化深度报告——包含口播逐段拆解、分镜头表、爆款文案库等可直接指导拍摄的产出。

**2026-07-28 重大重组**：已从 6 Tab/GBK 乱码/半部署状态精简为 4 Tab 清洁版本。所有已知 Bug 清账，前端唯一真相源为 `frontend/web_player.html`，由 Flask 后端 `transcribe_server.py` 直接 serve。

### 当前技术栈

| 层面 | 当前运行版（Flask） | v2.0 重构版（已就绪，待切换） |
|------|-------------------|---------------------------|
| 后端框架 | Flask + threading | FastAPI + Celery Worker |
| 任务存储 | 内存 dict（带 `jobs_lock`） | PostgreSQL 16 |
| 消息/进度 | 前端 2 秒轮询 | Redis 7 + WebSocket 实时推送 |
| 文件存储 | 本地 temp 目录（用完即删） | MinIO 对象存储 |
| 部署 | 单命令 `python transcribe_server.py` | Docker Compose 6 容器 |
| 限流/监控 | 已加 `/health` | slowapi + /ready + Prometheus |
| 前端 | 原生 HTML/CSS/JS（4 Tab） | 同左 |
| 语音转写 | Whisper（CPU/GPU 自动检测） | Whisper（WHISPER_DEVICE 可配） |
| LLM 分析 | SiliconFlow / Ollama / 智谱 | 同左 + AES-256-GCM 加密管理 Key |

### 支持格式

- **视频格式**：MP4 / MOV / AVI / WebM
- **文件大小**：最大 600MB
- **音频要求**：需包含音轨（静音视频仅做画面分析）

## 二、核心功能模块

### 2.1 视频上传与预览

- 拖拽或点击上传视频文件
- 自动提取视频预览（左侧面板）
- 实时显示视频元数据：时长、分辨率、帧率、总帧数、文件大小、音轨信息
- 自动识别横屏 / 竖屏方向

### 2.2 画面智能分析

系统按固定间隔抽取关键帧，对每一帧执行以下分析：

| 分析维度 | 说明 |
|----------|------|
| **RGB 色彩** | 提取平均 R/G/B 通道值，识别主色调 |
| **亮度** | 计算画面整体亮度（0-1） |
| **运动检测** | 通过帧间差异计算运动强度 |
| **文字密度** | 检测画面中文字区域占比 |
| **皮肤检测** | 识别人物/面部区域占比 |
| **白底检测** | 识别产品展示类白底背景 |
| **蓝色检测** | 识别设备屏幕/软件界面 |
| **暗光检测** | 识别电影感/夜景画面 |
| **色调/饱和度** | 提取 HSV 色彩空间信息 |
| **构图类型** | 自动判断镜头类型（特写/中景/远景等） |

### 2.3 内容类型智能识别

基于多维画面特征权重矩阵，系统自动识别 **9 种内容类型**：

| 类型 | 标识 | 典型特征 | 适用场景 |
|------|------|----------|----------|
| 电商带货 | ECOMMERCE | 白底背景、产品展示、字幕密集、稳定镜头 | 抖音/小红书带货视频 |
| Vlog 日志 | VLOG | 人物出镜、生活场景、运动镜头、字幕叙事 | 生活分享、旅行记录 |
| 医美医疗 | MEDICAL | 设备界面、皮肤特写、治疗画面、诊所环境 | 医美项目讲解、医学科普 |
| 美食类 | FOOD | 暖色调、高饱和度、美食特写、餐具 | 美食制作、餐厅探店 |
| 教育知识 | EDUCATION | 高文字密度、屏幕内容、讲师出镜、结构化讲解 | 知识科普、技能教学 |
| 影视剪辑 | VIDEO_EDIT | 暗光色调、多场景切换、快速切换、电影感 | 影视解说、情景短剧 |
| 直播带货 | LIVE_COMMERCE | 价格标注、商品展示、主播出镜、高信息密度 | 直播间录制内容 |
| 动漫/CG | ANIMATION | 高饱和色彩、非真实人像、蓝紫色调 | 动画、CG 内容 |
| 屏幕录制 | SCREEN_RECORD | 蓝色屏幕界面、屏幕文字密集、无人物 | 软件教程、操作演示 |

**识别机制**：每种类型定义 5-7 条特征信号（含正向加分和负向减分），系统对所有帧取通过率加权求和，得分最高者即为识别结果，同时输出匹配特征清单和可信度评分。

### 2.4 语音转写（Whisper）

- **后端服务**：`transcribe_server.py`，默认端口 `8766`
- **API 接口**：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/transcribe` | POST | 上传视频，启动转写任务，返回 `job_id` |
| `/api/status/{job_id}` | GET | 查询任务状态（extracting/transcribing/analyzing/done/error/no_audio） |
| `/api/result/{job_id}` | GET | 获取转写结果（分段文本 + 时间戳） |

- **转写流程**：上传视频 → 提取音频 → Whisper 转写 → 结果分析
- **进度追踪**：实时显示 Whisper 转写进度百分比和预估剩余时间
- **分段输出**：按时间戳分段，支持关键词高亮

### 2.5 关键词提取

对转写文本进行 NLP 分析，提取四类关键词：

| 类别 | 说明 |
|------|------|
| 高频词 | 出现 ≥2 次的中文词汇（过滤停用词） |
| 动作词 | 推荐、介绍、讲解、分享、展示、演示等 |
| 情绪词 | 非常、特别、真的、喜欢、完美等 |
| 产品/核心词 | 长度 ≥3 且有意义的词汇 |

### 2.6 文案脚本生成

根据内容类型对应的文案结构（如电商视频的"开场→产品展示→演示→结尾"），结合语音转写内容，自动生成分段文案脚本。

### 2.7 多维数据可视化

使用 Chart.js 渲染四类图表：

| 图表 | 类型 | 展示内容 |
|------|------|----------|
| RGB 色彩趋势 | 折线图 | R/G/B 三通道随时间变化 |
| 亮度 & 运动 & 文字 | 折线图（双 Y 轴） | 亮度、运动强度、文字密度趋势 |
| 文字密度 | 柱状图 | 各帧文字占比 |
| 色调分布 | 环形图 | Top 6 主色调占比 |

### 2.8 文案结构拆解

- **场景分段**：根据内容类型的专属 Phase 逻辑，将视频拆分为多个场景段落
- **每段信息**：场景名称、时间段、持续时长、特征标签（人物/设备/字幕/高饱和/暗光）、画面特征数值、对应语音内容、缩略图
- **脚本对照表**：段落 / 时间 / 时长 / 画面特征 / 语音内容 / 文案方向

### 2.9 完整分析报告

自动生成 Markdown 格式报告，包含：

1. 基本信息表（时长、分辨率、方向、帧率、文件大小）
2. 内容类型识别（类型、描述、特征、可信度评分、匹配特征清单）
3. 核心指标（平均亮度、平均运动、场景切换次数）
4. 场景时间线
5. 语音识别全文
6. 帧数据明细表

支持一键下载报告（.md）和帧图片打包下载。

### 2.10 大模型深度文案拆解报告（硅基流动）

> **仅在 v3-live / v3-server 版本中提供**，v1/v2/v3 构建版无此功能。

这是项目最新增加的能力：将视频 **画面分析结果 + Whisper 转写全文 + 视频元数据** 打包发送给大语言模型（LLM），由模型基于"5 位一体方法论"自动生成九节结构化深度分析报告。

#### 支持的大模型服务商

| 服务商 | 标识 | 说明 |
|--------|------|------|
| **硅基流动** | SiliconFlow | 默认选择，API 兼容 OpenAI 格式，获取 Key：`siliconflow.cn` → 个人中心 → API Key |
| **Ollama** | Ollama | 本地大模型，需启动 `ollama serve` 并拉取模型（如 `ollama pull llama3.1`） |
| **智谱** | Zhipu | 智谱清言 API，获取 Key：`open.bigmodel.cn` |

#### 分析方法论

```
叙事主权利破局 + 反资共情 + 5A人群流转 + 实效卖点种草 + 信任建立体系
                          ↓
            大模型按九节结构拆解生成报告
```

- **叙事主权利破局**：分析开篇如何抓住用户注意力
- **反资共情**：提取与目标受众的情感共鸣点
- **5A 人群流转**：识别 Aware / Appeal / Ask / Act / Advocate 各阶段的文案打法
- **实效卖点种草**：拆解产品卖点的植入方式和表达技巧
- **信任建立体系**：分析社会证明、权威背书、用户评价等信任构建手段

#### 交互流程（三步走）

```
┌─────────────────────────────────────────────────────────┐
│  Step 1: 选择 AI 服务商 + 输入 API Key                   │
│  ├ 选 SiliconFlow / Ollama / 智谱                       │
│  ├ 输入 API Key（仅浏览器本地使用，不上传任何服务器）      │
│  └ 点「验证 Key」→ 后端代理验证 → 拉取可用模型列表        │
├─────────────────────────────────────────────────────────┤
│  Step 2: 选择模型 + 启动分析                             │
│  ├ 从可用模型列表中选择一个模型（如 Qwen、DeepSeek 等）    │
│  └ 点「启动深度分析」                                    │
├─────────────────────────────────────────────────────────┤
│  Step 3: 查看报告 + 下载                                │
│  ├ 报告 Markdown → HTML 渲染显示                        │
│  ├ 「下载深度报告」→ 导出 .md 文件                       │

└─────────────────────────────────────────────────────────┘
```

#### 后端 API 接口（新增）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/test-api-key` | POST | 验证 API Key，返回可用模型列表 |

```json

  },
  "analysis": { /* 完整 analysisResult — 帧数据、内容类型、场景分段等 */ },
  "video_meta": { "width": 1080, "height": 1920, "fps": 30 },
  "api_key": "sk-xxxxxxxx",
  "model": "Qwen/Qwen2.5-7B-Instruct",
  "provider": "siliconflow",
  "ollama_base": "http://localhost:11434"
}
```

#### 架构特点

```
┌─────────────┐     ┌──────────────────┐     ┌─────────────────────┐
│  浏览器前端   │────▶│  transcribe_server │────▶│  SiliconFlow / Ollama │
```

### 已知问题与修复记录

> **行号偏移 Bug**（已修复）：`web_player.html` 经多次修改后，实际行号与 `build_v3.py` 中硬编码的行范围产生偏移（偏移约 17 行），导致 `DOWNLOAD_FRAMES`、`INIT_CODE`、`RENDER_REPORT` 等函数体丢失，表现为上传按钮无响应。修复方式为更新 `build_v3.py` 中的行范围常量。

### 7.3 API 一览（v2.0）

所有业务接口前缀 `/api/v1`，均带速率限制。

| 方法 | 路径 | 说明 | 限流 |
|------|------|------|------|
| POST | `/api/v1/upload` | 上传视频文件 | 5/分钟 |
| POST | `/api/v1/transcribe` | 启动 Whisper 异步转写 | 5/分钟 |
| GET | `/api/v1/transcribe/{job_id}` | 获取转写结果（分段+全文+关键词） | 60/分钟 |
| POST | `/api/v1/analyze` | 启动 LLM 深度分析 | 10/分钟 |
| GET | `/api/v1/analyze/{job_id}` | 获取分析报告 | 60/分钟 |
| POST | `/api/v1/test-api-key` | 校验 LLM API Key | 10/分钟 |
| GET | `/api/v1/jobs` | 任务列表（支持分页+过滤） | 30/分钟 |
| GET | `/api/v1/jobs/{job_id}` | 单任务详情 | 60/分钟 |
| POST | `/api/v1/jobs/{job_id}/cancel` | 取消进行中任务 | 10/分钟 |
| DELETE | `/api/v1/jobs/{job_id}` | 删除任务及关联文件 | 5/分钟 |
| WS | `/api/v1/ws/jobs/{job_id}` | **WebSocket 实时进度推送** | — |

**典型流程**：
```
POST /upload → 得 job_id
POST /transcribe → WS 连 /ws/jobs/{job_id} 收实时进度
GET /transcribe/{job_id} → 得转写结果
POST /analyze → WS 实时进度
GET /analyze/{job_id} → 得深度报告
```
