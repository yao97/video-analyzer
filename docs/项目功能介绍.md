# Video Content Analyzer — 项目功能介绍

> 短视频竞品反向拆解工具：上传视频 → Whisper 语音转写 → 画面特征分析 → 大模型深度文案拆解 → 九节结构化报告（含分镜头表、爆款文案库、团队落地执行要点）。

---

## 一、项目概述

**Video Content Analyzer（VCA）** 是一款面向短视频编导团队的竞品反向拆解工具。上传竞品视频后，系统自动完成画面特征分析、Whisper 语音转写、关键词提取，并可将「画面分析 + 转写全文 + 视频元数据」打包发送给大语言模型，生成九节结构化深度报告——包含口播逐段拆解、分镜头表、爆款文案库、可复刻对标行业与团队落地执行要点等可直接指导拍摄的产出。

**当前状态（2026-08-02）**：单体 Flask 服务（一个进程同时提供 API 与前端静态页），前端为 4 Tab 清洁版本，中文无乱码。`v2.0` FastAPI + Docker 版本已归档至 `archive/legacy-fastapi-app/`，**不作为当前运行环境**（详见第七节）。所有历史已知 Bug 均已清账。

### 当前技术栈

| 层面 | 当前运行版（单体 Flask） | 历史 v2.0（已归档，非运行） |
|------|------------------------|---------------------------|
| 后端框架 | Flask 3 + threading（单进程） | FastAPI + Celery Worker |
| 任务存储 | 内存 `dict`（带线程锁） | PostgreSQL 16 |
| 进度推送 | 前端轮询 `GET /api/status` | Redis + WebSocket 实时推送 |
| 文件存储 | 系统 temp 目录（用完即删） | MinIO 对象存储 |
| 部署 | `python transcribe_server.py` 或 Docker 单体镜像 | Docker Compose 6 容器 |
| 前端 | 原生 HTML / CSS / JS（4 Tab） | 同左 |
| 语音转写 | Whisper（CPU / GPU 自动检测） | Whisper（设备可配） |
| LLM 分析 | SiliconFlow / Ollama / 智谱 | 同左 + AES-256-GCM 加密管理 Key |

### 支持格式

- **视频格式**：MP4 / MOV / AVI / WebM
- **文件大小**：最大 600 MB
- **音频要求**：需包含音轨（纯画面视频仅做画面分析，无语音转写）

## 二、核心功能模块

### 2.1 视频上传与预览

- 拖拽或点击上传视频文件
- 自动提取视频预览（左侧面板）
- 实时显示元数据：时长、分辨率、帧率、总帧数、文件大小、音轨信息
- 自动识别横屏 / 竖屏方向

### 2.2 画面智能分析

系统按固定间隔抽取关键帧，在浏览器端用 Canvas 对每一帧执行特征分析（无需服务端算力）：

| 分析维度 | 说明 |
|----------|------|
| **RGB 色彩** | 提取平均 R / G / B 通道值，识别主色调 |
| **亮度** | 计算画面整体亮度（0-1） |
| **运动检测** | 通过帧间差异计算运动强度 |
| **文字密度** | 检测画面中文字区域占比 |
| **皮肤检测** | 识别人物 / 面部区域占比 |
| **白底检测** | 识别产品展示类白底背景 |
| **蓝色检测** | 识别设备屏幕 / 软件界面 |
| **暗光检测** | 识别电影感 / 夜景画面 |
| **色调 / 饱和度** | 提取 HSV 色彩空间信息 |
| **镜头类型** | 自动判断（人物特写 / 人物中景 / 产品展示 / 暗光场景 / 蓝色场景） |

### 2.3 语音转写（Whisper）

- **后端服务**：`backend/transcribe_server.py`，默认端口 `8766`，同时直接 serve 前端页面
- **转写流程**：上传视频 → 提取音频 → Whisper 转写 → 结果分析
- **进度追踪**：轮询 `GET /api/status/{job_id}` 实时显示状态（extracting / transcribing / analyzing / done / error / no_audio）
- **分段输出**：按时间戳分段，支持关键词高亮

**相关接口**：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/transcribe` | POST | 上传视频，启动转写任务，返回 `job_id` |
| `/api/whisper-models` | GET | 列出可用 Whisper 模型（tiny / base / small / medium / large 等） |
| `/api/status/{job_id}` | GET | 查询任务状态 |
| `/api/result/{job_id}` | GET | 获取转写结果（分段文本 + 时间戳 + 关键词） |
| `/api/video-meta` | GET / POST | 读取或写入视频元数据（时长 / 分辨率 / 帧率等） |

### 2.4 关键词提取

对转写文本进行 NLP 分析，提取四类关键词：

| 类别 | 说明 |
|------|------|
| 高频词 | 出现 ≥2 次的中文词汇（过滤停用词） |
| 动作词 | 推荐、介绍、讲解、分享、展示、演示等 |
| 情绪词 | 非常、特别、真的、喜欢、完美等 |
| 产品 / 核心词 | 长度 ≥3 且有意义的词汇 |

### 2.5 文案脚本生成

根据语音转写内容，自动生成分段「视频文案脚本」，呈现每段口播对应的文案方向，便于编导快速对照与改写。

### 2.6 帧预览与打包下载

- 关键帧网格预览，每帧带特征标签（人物 / 设备·蓝 / 白底 / 暗光）
- 一键将「关键帧图片 + Markdown 报告」打包为 ZIP 下载（基于前端 `jszip.min.js`，无需服务端参与）

### 2.7 完整分析报告

自动生成 Markdown 格式报告，包含：

1. 基本信息表（时长、分辨率、方向、帧率、文件大小）
2. 画面特征汇总（各维度均值与占比）
3. 语音识别全文（逐段 + 时间戳）
4. 关键词（高频 / 动作 / 情绪 / 产品）
5. 帧数据明细表
6. 深度拆解（若已执行，嵌入九节报告）

支持一键下载 `.md` 报告，或通过 `POST /api/save-export` 将报告与帧图落盘到 `exports/` 目录（生成 `html / markdown / pic` 三个子目录）。

### 2.8 大模型深度文案拆解报告

将视频「画面分析结果 + Whisper 转写全文 + 视频元数据」打包发送给大语言模型（LLM），由其按**九节格式**自动生成结构化深度分析报告。该功能是当前部署版本（`web_player.html`）的内置能力，**不再区分"专属版本"**。

#### 支持的大模型服务商

| 服务商 | 标识 | 说明 |
|--------|------|------|
| **硅基流动** | SiliconFlow | 默认选择，API 兼容 OpenAI 格式；提供 DeepSeek、通义千问等开源模型 |
| **Ollama** | Ollama | 本地大模型，需启动 `ollama serve` 并拉取模型（如 `ollama pull qwen2.5`） |
| **智谱** | Zhipu | 智谱清言 GLM 系列，Key 获取：`open.bigmodel.cn` |

#### 九节报告结构

| 节 | 内容 |
|----|------|
| 一句话总结 | 核心结论 · 流量打法 · 叙事主权破局点（三点箭头连接） |
| 第一节 · 原文基础信息 | 逐字稿全文（繁转简）+ 表层口播逻辑 |
| 第二节 · 深度反向拆解 | 风格调性、观众心理路径、底层情绪、叙事主权 4 步、跑量优势 |
| 第三节 · 口播逐段拆解 | 表格：预估时长 / 模块 / 原文 / 核心作用 / 叙事主权标注 / 算法增益 / 5A 标注 |
| 第四节 · 分镜头拆解 | 表格：镜头编号 / 时长 / 景别运镜 / 画面内容 / 对应口播 / 情绪流转 / 视觉实锤 |
| 第五节 · 5A 人群流转 | 表格：人群层级 / 作用强度 / 核心流转价值 / 流转路径 |
| 第六节 · 爆款文案库 | 表格：替代文案（开场钩子 / 卖点 / 效果 / 背书 / 行动召唤） |
| 第七节 · 可复刻对标行业 | 3-5 个相邻品类的"推翻旧叙事 → 建立新标准" |
| 第八节 · 团队落地执行要点 | 5-6 条可执行指令（叙事一致性 / 实锤优先 / 背书强化 / 反攻击预案等） |

> **叙事主权方法论**：破霸权 → 建标准 → 立人设 → 收闭环；**5A 标注**：A1（3 秒）/ A2（前三分位）/ A3（中段）/ A4（后三分位）/ A5（结尾）。

#### 交互流程（三步走）

```
Step 1  选择 AI 服务商 + 输入 API Key
        ├ 选 SiliconFlow / Ollama / 智谱
        ├ 输入 Key（仅浏览器内存，不落库）
        └ 点「验证 Key」→ 后端代理校验 → 拉取可用模型列表
Step 2  选择模型 + 启动分析
        ├ 从模型列表选择（如 DeepSeek / Qwen / GLM）
        └ 点「启动深度分析」→ 异步任务，轮询进度
Step 3  查看报告 + 下载
        ├ Markdown → HTML 渲染显示
        ├ 「下载深度报告」→ 导出 .md
        └ 「重新分析」→ 回到 Step 1 / Step 2
```

#### 后端 API 接口（深度分析）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/test-api-key` | POST | 校验 API Key，返回可用模型列表 |
| `/api/analyze-copy` | POST | 发送转写文本 + 分析数据，LLM 异步生成九节报告，返回 `job_id` |
| `/api/analyze-status/{job_id}` | GET | 深度分析任务状态 |
| `/api/analyze-result/{job_id}` | GET | 获取九节深度报告内容 |

**请求体 `/api/analyze-copy` 示例**：

```json
{
  "transcription": {
    "text": "语音转写全文",
    "language": "zh",
    "segments": [{ "start": 0.0, "text": "..." }],
    "keywords": { "highFreq": [], "actions": [], "emotions": [], "products": [] }
  },
  "analysis": { "frames": [], "averages": {} },
  "video_meta": { "width": 1080, "height": 1920, "fps": 30 },
  "api_key": "sk-xxxxxxxx",
  "model": "deepseek-ai/DeepSeek-V3",
  "provider": "siliconflow",
  "ollama_base": "http://localhost:11434"
}
```

**安全说明**：API Key 仅保存在浏览器内存（`<input type="password">`），随请求发送到本地后端做代理转发，后端不落库、不记录、不存储。刷新页面即清除，切换服务商需重新输入。

## 五、构建系统

### build_v3.py 工作原理

`build_v3.py` 是一个 Python 构建脚本：从 `web_player.html` 中按行号区间抽取代码块，重新拼接为 `web_player_v3.html`，并内联必要资源。运行后会执行自校验：

- **4 Tab 校验**：确认输出含 `tabSpeech / tabFrames / tabDeepReport / tabReport`
- **中文守卫（mojibake guard）**：扫描输出是否出现 GBK 误编码乱码，发现即报错退出
- **禁止内容检测**：确认不含已下线的内容类型识别 / Chart.js 死代码

**已知问题与修复记录**：

> **行号偏移 Bug（已修复）**：`web_player.html` 经多次修改后，实际行号与 `build_v3.py` 中硬编码的行范围产生偏移（约 17 行），导致部分函数体丢失、上传按钮无响应。修复方式为同步更新 `build_v3.py` 中的行范围常量，并加入上述自校验防止回归。

## 七、后端系统架构

### 7.1 当前架构：单体 Flask 服务

一个 Python 进程（`transcribe_server.py`，1912 行）同时承担：

- 转写 / 深度分析 API
- 前端静态页 serve（`/` 与 `/web_player.html` 均返回 `web_player.html`）
- JSZip 等前端依赖分发

**启动方式**：

```bash
# 方式一：双击 start_backend.bat（已配置 venv 与 8766 端口）
# 方式二：手动
cd C:\Users\EDY\Projects\video-analyzer\backend
python transcribe_server.py --host 0.0.0.0 --port 8766 --model small
```

启动后浏览器访问 `http://<本机IP>:8766/` 即前端页面。临时文件（音频 / 视频 / WAV）写入系统 temp 目录，不污染仓库。

### 7.2 历史 v2.0（已归档，非运行）

FastAPI + Celery + PostgreSQL + Redis + MinIO + Docker Compose 的生产级架构源码保留在 `archive/legacy-fastapi-app/`，包含 WebSocket 实时进度、任务持久化、AES 加密 Key 管理等能力。当前未作为运行环境，如未来切换可从此处恢复。

### 7.3 当前 API 一览（单体 Flask）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` · `/web_player.html` | 前端首页（返回 `web_player.html`） |
| GET | `/jszip.min.js` | 前端 ZIP 打包依赖 |
| POST | `/api/transcribe` | 上传视频，启动 Whisper 转写，返回 `job_id` |
| GET | `/api/whisper-models` | 列出可用 Whisper 模型 |
| GET | `/api/status/{job_id}` | 转写任务状态 |
| GET | `/api/result/{job_id}` | 转写结果（segments + keywords） |
| GET / POST | `/api/video-meta` | 视频元数据读写 |
| POST | `/api/save-export` | 将报告 + 帧图保存到 `exports/`（html / markdown / pic） |
| POST | `/api/test-api-key` | 校验 LLM API Key，返回可用模型列表 |
| POST | `/api/analyze-copy` | 发送数据给 LLM，异步生成九节深度报告，返回 `job_id` |
| GET | `/api/analyze-status/{job_id}` | 深度分析任务状态 |
| GET | `/api/analyze-result/{job_id}` | 深度报告内容 |

> 典型流程：上传 `POST /api/transcribe` → 轮询 `GET /api/status` → 取结果 `GET /api/result` → （可选）`POST /api/analyze-copy` → 轮询 `GET /api/analyze-status` → 取报告 `GET /api/analyze-result`。

### 7.4 安全设计

| 项 | 当前 Flask 单体 | 历史 v2.0（已归档） |
|----|----------------|-------------------|
| CORS | 白名单 `_ALLOWED_ORIGINS`（127.0.0.1 / localhost / 192.168.x） | 同左 |
| LLM Key | 前端传入，后端明文代理转发，不落库 | 服务端 AES-256-GCM 加密管理 |
| 命令执行 | 参数列表调用 ffmpeg（无 `shell=True`） | 同左 |
| 限流 | 无 | slowapi 按 IP 限制写接口 |
| 文件校验 | 基本（大小 / 格式） | MIME + 大小校验 |
| 健康检查 | 无（端口存活即服务） | `/health` `/ready` `/metrics` |
